# 订单详情重推浪潮

> 记录 legacy 与重构版的 TMC 订单详情“重推浪潮”功能。本文仅覆盖国内因公 TMC 订单，因私 tourist / public 订单不展示该入口。

## Legacy 行为

酒店、机票、火车票 TMC 订单详情均使用同一套浪潮重推能力。

| 阶段             | Legacy 接口                                     | 参数 / 数据       |
| ---------------- | ----------------------------------------------- | ----------------- |
| 判断是否显示入口 | `TmcApiOrderUrl-Order-CheckInspurRepush`        | `{ Id: orderId }` |
| 获取订单旅客     | `TmcApiOrderUrl-Order-GetOrderPassengers`       | `{ Id: orderId }` |
| 搜索推送预订人   | `TmcApiOrderUrl-Order-GetLinkmans?name=${name}` | `Data` 为空       |
| 确认重推         | `TmcApiOrderUrl-Order-RePush`                   | 数组              |

入口显示逻辑由后端决定：详情页加载时调用 `CheckInspurRepush`，返回真值则展示底部“重推浪潮”按钮。前端不再按订单状态、产品类型做二次判断。

Legacy 弹窗交互：

1. 打开弹窗后加载订单旅客和可推送预订人。
2. 用户先勾选需要重推的旅客。
3. 每个旅客可以选择一个推送预订人，也可以不指定。
4. 提交 `RePush`，后端返回 `Message` 后直接提示。

提交数组项结构：

```ts
{
  OrderId: string;
  PassengerId: string;
  LinkmanId: string;
  LinkmanName: string;
  LinkmanMobile: string;
}
```

## 重构版对齐

当前 H5 / Web 已按 legacy 补齐：

| 产品           | H5     | Web    | 说明                 |
| -------------- | ------ | ------ | -------------------- |
| 酒店订单详情   | 已接入 | 已接入 | 替换原“即将上线”占位 |
| 机票订单详情   | 已接入 | 已接入 | 替换原“即将上线”占位 |
| 火车票订单详情 | 已接入 | 已接入 | 补齐原缺失入口       |

实现要点：

1. `channel` 必须为 `tmc` 才请求 `CheckInspurRepush`，避免因私订单误打 TMC 接口。
2. API 层保留 `RePush` 的后端 `Message`，用于成功提示。
3. 弹窗使用移动端友好的列表表单，不沿用 legacy 横向表格。
4. 未选择任何旅客时前端阻止提交。
5. 未指定推送预订人时按 legacy 提交空联系人字段。
6. 提交成功后刷新当前订单的重推显示状态和订单详情缓存。

## 注意事项

- 该功能是 TMC 与浪潮系统之间的补偿推送，不属于普通订单下单、支付、取消、退改签链路。
- 是否允许重推以 `CheckInspurRepush` 为准，前端不缓存长期结果。
- 如后端后续要求所有旅客必须指定推送预订人，需要在弹窗提交前增加必填校验。
