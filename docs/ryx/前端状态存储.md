# 前端状态存储

本文说明 H5 / Web 迁移实现中乘客选择、下单快照、改签上下文的前端存储边界。核心原则是：**当前选人统一走 `passenger-selection`，下单与改签只保存业务上下文快照**。

## 存储分类

| 类型 | 存储 | Key | 职责 | 清理时机 |
| --- | --- | --- | --- | --- |
| 当前选人 | `localStorage` | `ryx_passenger_selection_${ProductType}` | 当前产品维度下用户选择的乘客/住客，是选人页面与列表/下单页共享的主来源 | 对应产品下单成功、显式清空、登录态切换等 |
| 下单快照 | `sessionStorage` | `ryx_flight_book_selection` / `ryx_train_book_selection` / `ryx_hotel_book_selection` | 进入下单页时固定本次订单所需的航班/车次/酒店、价格、政策、搜索参数等上下文 | 下单成功、离开流程或重新选择产品 |
| 改签上下文 | `sessionStorage` | `ryx_flight_exchange_session` / `ryx_train_exchange_session` | 保存改签入口订单、票 ID、改签接口返回信息等上下文 | 改签下单成功、进入普通列表、手动清理 |

## ProductType 与选人 Key

`ProductType` 与 legacy `FlightHotelTrainType` 对齐：

| 产品 | ProductType | 当前选人 Key |
| --- | ---: | --- |
| 机票 | `1` | `ryx_passenger_selection_1` |
| 酒店 | `2` | `ryx_passenger_selection_2` |
| 火车 | `3` | `ryx_passenger_selection_3` |
| 国际酒店 | `4` | `ryx_passenger_selection_4` |
| 国际机票 | `5` | `ryx_passenger_selection_5` |
| 租车 | `6` | `ryx_passenger_selection_6` |

代码入口：

- H5：`apps/h5/src/lib/passenger-selection.ts`
- Web：`apps/web/src/lib/passenger-selection.ts`
- 使用方式：`usePassengerSelection(ProductType.X)`、`savePassengerSelection(ProductType.X, items)`、`clearPassengerSelection(ProductType.X)`

## 边界规则

1. 当前选人以 `ryx_passenger_selection_${ProductType}` 为准。
   列表页、下单页、选人页都应通过 `passenger-selection` 模块读写，不直接拼 key。

2. 下单快照不是当前选人的主来源。
   `ryx_*_book_selection` 用来固定进入下单页时的业务上下文。例如火车会保存 `passengers` 快照，因为车次座席选择和因公政策校验依赖“选择座席那一刻”的乘车人。

3. 改签上下文不是当前选人的主来源。
   `ryx_*_exchange_session` 保存改签订单/票据上下文。进入改签流程时，如果后续列表/下单页需要按普通链路读取旅客，应同步写入对应的 `ryx_passenger_selection_${ProductType}`。

4. 不建议把三类状态合成一个统一大对象。
   `localStorage` 的当前选人需要跨页面和返回链路保留；`sessionStorage` 的下单快照和改签上下文只服务当前流程。合并会增加清理复杂度，也容易让下单页读取到过期或不匹配的上下文。

## 产品链路说明

### 机票

- 当前乘机人：`ryx_passenger_selection_1`
- 下单快照：`ryx_flight_book_selection`
- 改签上下文：`ryx_flight_exchange_session`
- 因公机票进入舱位/下单链路时，通过 `usePassengerSelection(ProductType.Flight)` 读取当前乘机人；改签入口会把原票乘机人写回 `ryx_passenger_selection_1`。

### 火车

- 当前乘车人：`ryx_passenger_selection_3`
- 下单快照：`ryx_train_book_selection`
- 改签上下文：`ryx_train_exchange_session`
- 因公火车列表页通过 `usePassengerSelection(ProductType.Train)` 读取乘车人；选择座席时会把当时的乘车人保存到 `ryx_train_book_selection.passengers`，用于下单页和政策上下文稳定。

### 酒店

- 当前住客：`ryx_passenger_selection_2`
- 下单快照：`ryx_hotel_book_selection`
- 酒店下单快照固定酒店、房型、价格计划、日期等信息；住客选择仍通过 `passenger-selection` 维护。

## 维护要求

- 新增产品或新增业务流程时，优先复用 `passenger-selection`，不要新增独立的“当前选人”存储。
- 只有当页面需要固定一次业务上下文时，才新增 `*_book_selection` 这类 session 快照。
- 只有跨页面改签/退改签流程需要订单上下文时，才新增 `*_exchange_session` 这类 session 状态。
- H5 与 Web 的存储 key、清理时机和注释应保持一致。
