# 差旅标准

本文档梳理 legacy 融易行国内差旅标准行为，供 H5/Web 迁移与后续体验补齐使用。国际机票/国际酒店不在本文档范围内。

## 结论

国内 legacy 中，完整差旅标准体系主要存在于因公 TMC 流程。因私 public 国内流程没有完整可用的差旅标准详情或过滤闭环，源码中有一些残留入口或注释代码，迁移时不应按有效能力处理。

差旅标准相关入口分为两类：

| 入口 | legacy 组件 | 作用 |
| ---- | ----------- | ---- |
| 差旅标准 | `ShowStandardDetailsComponent` | 展示后端 `Policy.*Description` 文案拆分后的列表 |
| 过滤差标 | `FilterPassengersPolicyComponent` | 在多人场景选择一个旅客作为标准过滤资源，或选择不过滤 |

`差旅标准` 不是结构化字段详情，只是文字列表。`过滤差标` 也不展示标准明细，只影响资源页展示、按钮颜色或可选集合。最终下单仍会基于所有已选旅客重新校验超标和可预订状态。

## 基础条件

`HrService.isSelfBookType()` 读取 `Staff.BookType`：

| 值 | 含义 | legacy 行为 |
| --- | ---- | ----------- |
| `StaffBookType.Self` | 仅能给自己预订 | 自动补当前登录人为乘客，限制添加他人 |
| `StaffBookType.All` 或空 | 可代订/可多人 | 允许添加员工旅客，部分页面支持按旅客过滤差标 |

源码：

- `beeantmobile-main/projects/ryx/src/app/hr/hr.service.ts`

## 因公 TMC 国内矩阵

| 产品 | 页面/场景 | 仅本人 | 多人/可订他人 | legacy 实际行为 |
| ---- | --------- | ------ | ------------- | ---------------- |
| 机票 | 查询页 | 显示 `差旅标准` | 不显示 | 点击后展示 `Policy.FlightDescription`，按逗号拆分 |
| 机票 | 航班列表页 | 无详情入口 | 无可见过滤入口 | `_ryx` 模板中 `过滤差标` 按钮条件为空，不可见 |
| 机票 | 舱位页 | 自动按本人标准 | 显示 `过滤差标` | 可选择旅客过滤舱位；改签场景不显示 |
| 火车 | 查询页 | 显示 `差旅标准` | 不显示 | 点击后展示 `Policy.TrainDescription`，按句号拆分 |
| 火车 | 列表页 | 自动按本人标准 | 无可见过滤入口 | `_ryx` 模板中 `过滤差标` 按钮被注释；服务层仍按 `isFilterPolicy` 计算颜色/过滤 |
| 酒店 | 查询页 | 显示 `差旅标准` | 不显示 | 点击后展示 `Policy.HotelDescription`，按句号拆分 |
| 酒店 | 酒店详情页 | 显示 `过滤差标` | 显示 `过滤差标` | 选择旅客后刷新房型按钮颜色；不展示标准详情 |

### 机票

查询页：

- `tmc-flight-search_ryx.page.html`：`*ngIf='isSelf'` 时显示 `差旅标准`。
- `tmc-flight-search_ryx.base.page.ts`：点击后读取 `Staff.Policy.FlightDescription`，按 `,` 拆分传给 `ShowStandardDetailsComponent`。

航班列表页：

- `tmc-flight-list_ryx.page.html` 中存在 `过滤差标` 按钮，但 `*ngIf=''` 为空，实际不可见。
- 列表进入舱位前会请求舱位差标策略，若多人且未选旅客会提示先添加旅客。

舱位页：

- `tmc-flight-item-cabins_ryx.page.html`：`!isSelf && !isExchange` 时显示 `过滤差标`。
- `tmc-flight-item-cabins_ryx.base.page.ts`：默认 `isSelf` 或只有一个旅客时自动过滤；多人时弹出 `FilterPassengersPolicyComponent`，选择旅客后重新计算舱位。

### 火车

查询页：

- `tmc-train-search_ryx.page.html`：`*ngIf='isSelf'` 时显示 `差旅标准`。
- `tmc-train-search_ryx.base.ts`：点击后读取 `Staff.Policy.TrainDescription`，按 `。` 拆分传给 `ShowStandardDetailsComponent`。

列表页：

- `tmc-train-list_ryx.page.html` 中 `过滤差标` 按钮被注释，实际不可见。
- `tmc-train-list_ryx.base.page.ts` 和 `tmc-train.service.ts` 仍保留 `filterPolicyTrains()`、`filterPassengerPolicyTrains()`，会基于当前 `isFilterPolicy` 旅客处理坐席颜色和过滤。

### 酒店

查询页：

- `tmc-hotel-search_ryx.page.html`：`*ngIf='isSelf'` 时显示 `差旅标准`。
- `tmc-hotel-search_ryx.base.page.ts`：点击后读取 `Staff.Policy.HotelDescription`，按 `。` 拆分传给 `ShowStandardDetailsComponent`。

详情页：

- `tmc-hotel-detail_ryx.page.html`：始终显示 `过滤差标`。
- `tmc-hotel-detail_ryx.base.page.ts`：默认取已选过滤旅客或第一个旅客，调用 `TmcApiHotelUrl-Home-Policy` 后按房型策略设置按钮颜色。
- 点击 `不过滤差标` 时，页面展示会变成不过滤状态，但进入预订页/下单前仍会携带所有房客进行校验。

## 因私 Public 国内矩阵

| 产品 | legacy 情况 | 迁移判断 |
| ---- | ----------- | -------- |
| 因私机票 | 舱位页模板/代码存在 `过滤差标` 残留，但 `_ryx` 入口被注释，TS 方法也被注释 | 不按有效能力迁移 |
| 因私火车 | `TmcTouristTrainUrl-Home-Policy` 相关逻辑被注释 | 不按有效能力迁移 |
| 因私酒店 | `onShowStandardDesc()` 直接 `return` | 不按有效能力迁移 |

## 颜色含义

legacy 在资源页使用颜色表达差标状态：

| 状态 | 颜色 | 含义 |
| ---- | ---- | ---- |
| 符合差标 | success/绿色 | 可预订且无超标规则 |
| 超标但可预订 | warning/橙色 | 有 `Rules`，通常需要提示或审批 |
| 不可预订 | danger/红色或 disabled | `IsAllowBook=false` 或无权限/满房 |

迁移时应避免把绿色理解为“预订按钮主色”。绿色只表示符合差标；若超标应明确用警示色，不能继续显示绿色。

## 迁移补齐体验建议

目标：在不改变后端校验语义的前提下，让用户明确知道“当前按谁的标准看资源”和“为什么超标/不可订”。

### 1. 详情入口

| 场景 | 建议 |
| ---- | ---- |
| 因公 + 仅本人 + 查询页 | 保留 `差旅标准`，点击展示本人差旅标准文案 |
| 因公 + 仅本人 + 资源页 | 可展示 `差旅标准`/当前标准入口，点击展示同一份文案 |
| 因公 + 多人/可订他人 | 默认展示 `过滤差标`，弹窗内选择旅客；不默认展示某个人的详情 |
| 因私国内 | 不展示差旅标准入口 |

详情弹窗内容优先保持 legacy 口径：使用后端 `Policy.FlightDescription`、`Policy.TrainDescription`、`Policy.HotelDescription` 文案拆分展示。结构化字段可作为增强，但需要明确标注为迁移增强，不应冒充 legacy 行为。

### 2. 过滤入口

| 产品 | 建议 |
| ---- | ---- |
| 机票 | 舱位页保留多人 `过滤差标`；查询页/列表页不强行加过滤入口 |
| 火车 | 为补齐体验，可在列表页增加可见 `过滤差标`，条件为因公、非仅本人、非改签/锁定、已选旅客数大于 1 |
| 酒店 | 酒店详情页保留 `过滤差标`；仅本人时也可显示当前本人标准入口，但过滤弹窗不是详情弹窗 |

### 3. 自订/多人条件

仅本人场景：

- 首页刷新或进入产品前应尽早刷新 `Staff/Get`、`Identity/Get`。
- 产品页自动补当前登录人为乘客。
- 不展示添加旅客入口。
- 资源页按本人差标计算颜色。

多人场景：

- 需要先选旅客。
- 默认可按第一个/当前 `isFilterPolicy` 旅客过滤展示。
- 必须允许用户切换过滤旅客或选择不过滤。
- 不过滤只影响展示，不跳过最终下单校验。

### 4. 超标详情

资源项上的超标详情优先来自接口返回的 `Rules`：

- 机票舱位：`FlightPolicy.Rules` / `Descriptions`。
- 火车坐席：`TrainPolicy.Rules`。
- 酒店房型：`HotelPolicy.Rules` 或房型 `roomPlan.Rules`。

建议点击资源项的差标提示或按钮旁状态时，展示当前资源的超标原因；不要把这类资源级 `Rules` 混同为个人全局差旅标准。

## 实现边界

迁移实现建议分两层：

1. 全局/个人差旅标准详情：只负责展示 `Staff.Policy.*Description`。
2. 资源级差标过滤与超标原因：只负责当前列表、舱位、坐席、房型的策略过滤和 `Rules` 展示。

这样可以避免三个混淆：

- 把 `BookType.Self` 当作因私。
- 把资源级超标原因当作个人全局标准。
- 把“不滤差标”误认为可以绕过最终下单校验。

## 当前迁移实现

- H5/Web `TravelPolicyDialog` 按 legacy 口径优先展示 `Policy.FlightDescription`、`Policy.TrainDescription`、`Policy.HotelDescription` 拆分后的文字列表；只有缺少描述文案时，才使用结构化字段作为兜底展示。
- 因公 TMC 仅本人场景继续使用 `差旅标准` 入口，不展示添加旅客入口。
- 因公 TMC 多人火车列表已补齐 `过滤差标` 入口，可选择某位旅客过滤坐席，也可选择不过滤差标；该选择只影响列表展示，点击预订时仍按全部已选旅客校验。
- 酒店详情与机票舱位继续沿用既有 `过滤差标` 交互，不新增因私国内入口。
