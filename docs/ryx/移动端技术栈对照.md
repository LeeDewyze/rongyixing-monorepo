# 移动端技术栈对照

## 结论

Legacy 移动端确实使用 Capacitor，不是纯原生 WebView，也不是只在浏览器中打开 H5。

Legacy 与当前项目的移动端路线一致，都是：

```text
前端页面
  -> Capacitor WebView 壳
  -> Android / iOS 原生工程
  -> Capacitor 原生插件
```

## Legacy

Legacy 源码位置：

```text
/Users/jiangjiankang/work/self/rongyixing/legacy/beeantmobile
```

Legacy 的技术栈：

| 分类 | 实际技术 |
| --- | --- |
| 前端框架 | Angular 12 |
| UI 框架 | Ionic Angular 6 |
| 原生桥接 | Capacitor 3.4.3 |
| 原生平台 | Android、iOS |
| 原生能力 | 自研 `@mycapacitor/*` 插件 |

`legacy/beeantmobile/package.json` 中包含：

- `@capacitor/android`
- `@capacitor/core`
- `@capacitor/ios`
- `@capacitor/cli`
- `@ionic/angular`
- 微信、支付宝、拨号、浏览器、剪贴板、启动外部 App、定位、相机、文件、推送、启动页等自研 Capacitor 插件

Legacy 的 Android 工程包含 `capacitor.settings.gradle`、
`capacitor.build.gradle`、`capacitor-android` 和
`capacitor-cordova-android-plugins`。iOS 工程的 `Podfile` 也直接引入
`Capacitor` 与 `CapacitorCordova`。

因此，Legacy 的 APK 本质上是 Angular/Ionic 页面运行在 Capacitor WebView
中，并通过 Capacitor 插件调用原生支付、拨号、外链和设备能力。

## 当前项目

当前项目的 Android 壳位于：

```text
apps/android-pad
```

当前技术栈：

| 分类 | 实际技术 |
| --- | --- |
| 前端框架 | React 19 |
| 类型系统 | TypeScript |
| 构建工具 | Vite |
| 原生桥接 | Capacitor 8.4.1 |
| 原生平台 | Android |
| 业务入口 | `@ryx/web` |

关键依赖位于 `apps/android-pad/package.json`：

- `@capacitor/android: ^8.4.1`
- `@capacitor/core: ^8.4.1`
- `@capacitor/cli: ^8.4.1`

当前 Android 壳支持两种页面加载方式：

1. **远程 H5 模式**：通过 `RYX_PAD_SERVER_URL` 加载服务器上的 Web 页面，H5/Web 发布后可以直接生效。
2. **内置静态包模式**：把 `apps/web/dist` 同步到 `apps/android-pad/web-dist`，由 APK 内置页面资源。

## 主要差异

| 项目 | Legacy | 当前项目 |
| --- | --- | --- |
| 前端 | Angular + Ionic | React + Vite |
| Capacitor | 3.4.3 | 8.4.1 |
| 原生平台 | Android + iOS | Android |
| 插件体系 | 已有较完整的自研插件 | 当前以 WebView 壳和远程 H5 为主 |
| 页面更新 | 可通过 HCP 等 Legacy 机制更新 | 远程 H5 模式下由服务器版本直接生效 |

当前项目是对 Legacy 的前端和工程现代化迁移，不是改成另一种移动端容器。
因此，登录、支付、拨号、地图、外链、返回键等涉及原生行为时，仍然需要
按 Legacy 的 Capacitor 插件能力逐项核对，不能因为都使用 Capacitor 就默认
插件 API 和行为完全兼容。

## 维护原则

- 业务页面继续维护在 `apps/h5` 或 `apps/web`，不要把业务逻辑复制到 Android 原生工程。
- 需要调用原生能力时，优先复用现有 Capacitor 能力；缺少能力时再新增插件或补充 Android 原生桥接。
- 远程 H5 模式解决页面快速发布问题，但不能自动补齐 Legacy 中已有的微信、支付宝、拨号等原生插件能力。
- 升级 Capacitor 主版本时，需要单独验证 Android 返回键、外部跳转、支付回调、文件上传和旧 WebView 兼容性。
